## Исходное состояние

База: `053707cccbe18b749258ad21c81bfd206d640246`, версия 3.9.5.
Пункт 1 был реализован в `main`; пункты 2–8 существовали только в рекомендациях.
Существующие `.min.*` файлы нуждались в воспроизводимой пересборке.

## Объём и критерии приёмки

- [x] **Первый уровень:** сохранить SSR, не запрашивать `level-1.js` повторно;
  при пустом select сохранить загрузку и AJAX с настроенным custom root.
- [x] **Stale while regenerate:** не удалять опубликованные файлы перед cron;
  проверять настройки перед выполнением cron; защищать генерацию блокировкой.
  Новое поколение публикуется только целиком, старые URL сохраняются.
- [x] **Одна выборка дерева:** один вызов `get_terms()` для генерации, индекс
  родителей в памяти; исключения, корень, сортировка и ошибки сохранены.
  Не обещать ровно один SQL-запрос при произвольных сторонних фильтрах.
- [x] **Файлы по родителю:** `lN-parent.js`, пустые файлы листьев, совместимость
  со старым форматом до первой генерации. Общие in-flight запросы и защита
  от запоздалых ответов при быстром изменении выбора.
- [x] **Defer:** обе зависимости получают стратегию на WordPress 6.3+;
  WordPress 5.8–6.2 сохраняет загрузку в футере.
- [x] **Условные ресурсы:** раннее обнаружение shortcode/block; поздний fallback
  для widget/template/synced block, CSS перед меню, JS в футере.
  Фильтр `mlcm_enqueue_assets` для раннего подключения в известных шаблонах.
- [x] **Сжатие и сервер:** gzip opt-in, по умолчанию выключен; не создавать
  и не переписывать `.htaccess`, не утверждать, что CDN использует sidecars.
- [x] **Мелкие исправления:** убрать debounce `change`, resize-стили и лишние
  data-атрибуты; Unicode с безопасными fallback; кэш версий в пределах запроса;
  очистка настроек и cron при uninstall; согласованные номера версии.

## Дополнительные дефекты, исправленные при проверке

- Неподдерживаемый `parent__in` в `WP_Term_Query` заменён в AJAX-пути на
  WordPress hierarchy cache; статическая генерация его не использует.
- Уникальные ID и связи label/select для нескольких меню.
- Сброс нижних уровней немедленно, игнорирование устаревших ответов.
- Явная зависимость `wp-block-editor`, одна регистрация ресурсов блока,
  `useBlockProps` и предел редактора из настроек плагина.
- Опции-boolean корректны и при возврате bool, и при строковом значении из БД.
- Удалён неработавший переключатель category base; URL формирует WordPress.
- Сообщения административного AJAX вставляются как текст, не как HTML.

## Тестирование

- Node/jsdom: заполненный и пустой SSR, custom root в fallback, новые и старые
  файлы, несколько меню, гонки ответов, reset, AJAX-ошибки, escaping.
  Каждый сценарий запускается на исходном и минифицированном frontend.
- Admin/editor: nonce административного запроса, блокировка кнопок на время
  операции, подтверждение удаления, escaping сообщений, регистрация блока,
  API version, `useBlockProps` и максимальная глубина; исходные и min-файлы.
- Реальный WordPress: дерево, корень, исключения, пустое дерево, глубина,
  количество `get_terms`, SSR без term-query, gzip, cron/coalescing,
  конкурентная генерация, query/link/publication failure, сохранение старого
  поколения, ручное удаление и uninstall.
- Отдельные PHP-процессы: страница без меню, ранний shortcode, поздний shortcode,
  widget и dynamic block; CSS должен печататься до меню и только один раз.
- CI: feature branch → PR → GitHub Actions; синтаксис PHP, матрица WordPress/PHP,
  frontend regression suite и проверка актуальности всех минифицированных файлов.

## Ограничения и откат

Кэшированный HTML не становится свежим от одного `versions.js`; он продолжает
использовать старый snapshot до purge/expiry. Автоматического purge и очистки
старых поколений нет: срок хранения page cache неизвестен плагину.
Удаление кэша явно убирает все поколения и включает fallback на старых страницах.

Для отката вернуть предыдущую версию плагина, заново сгенерировать legacy-файлы
её генератором и очистить page/CDN cache. Новый формат не следует копировать
поверх legacy-файлов. Тесты запускаются только в одноразовой БД.

## Проверенные API

Поведение `defer` и зависимостей сверено с
[wp_enqueue_script](https://developer.wordpress.org/reference/functions/wp_enqueue_script/).
Параметры выборки сверены с
[WP_Term_Query](https://developer.wordpress.org/reference/classes/wp_term_query/__construct/).
Поздняя печать CSS использует
[wp_print_styles](https://developer.wordpress.org/reference/functions/wp_print_styles/).
